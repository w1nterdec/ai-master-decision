## 三、结论

**Phase 4.0：有条件通过。**

满足全部 12 条工程验收标准；"有条件"的原因**不在代码**，而在数据状态：

1. 全部 10 条路径的 2028 招生资格未确认（L-01）；
2. 83 个来源未登记、207 条候选映射未人工核验（L-02/L-04）；
3. 因此系统当前**不输出任何可比较分数、不输出任何择校结论**——这是设计意图，不是缺陷。

在解除上述条件之前，任何"最终择校结论"都不得对外发布。

## 四、对四个收尾问题的回答

### 1. Phase 4.0 是否达到验收标准？
工程验收标准 12/12 通过；因数据前提未满足，整体判定为**有条件通过**。

### 2. 哪些功能已经真实测试？
- 三级权重：归一、传播、负权重、零权重分组（10 项）
- 证据闸门：评分合法性、来源存在性/核验状态/路径适用性/指标支持性/年份、候选不升级、冲突阻断（40 项）
- 覆盖率：指标数覆盖率、权重覆盖率、情景独立判断、阈值可配、缺失不补零（10 项）
- 硬约束：三态与 2028 四分支（9 项）
- 双目标：相关度差异、必备分组、2028 门槛、排除/待核验（13 项）
- 导入：幂等、年份/学院/路径角色隔离（9 项）
- 黄金：与 Phase 3.7C 实测逐格比对 4 场景（5 项）
- 端到端：DB → 引擎 → 落库（4 项）
全部 122 项在干净虚拟环境中实际执行通过，**未伪造任何通过结果**。

### 3. 哪些功能仍然缺失？
- 证据核验工作台（解锁评分的前置，P0）
- 2028 目录录入与资格核验（P0）
- 权重/情景的用户确认与编辑界面（P1）
- Web 可视化、PDF 报告、GitHub 集成（按需求本阶段不做）
- 调剂与直接就业的推荐算法（本阶段仅建结构与状态）
- 招生人数结构化录入、导师/资源人工登记（P2）
- Microsoft Excel 桌面端兼容性验证（L-17）
详见 `docs/known_limitations.md`。

### 4. 是否可以进入 Phase 4.1 Web 可视化开发？
**可以，但必须限定范围。**
建议 Phase 4.1 首批只做：证据核验工作台、待核问题看板、覆盖率与状态面板、
权重/情景编辑器（服务层已就绪）。
**不建议**在 2028 资格与来源核验完成前开发排行榜、推荐位、择校结论页——
在当前数据状态下，任何排名都缺乏证据基础。
