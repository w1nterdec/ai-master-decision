## 3. V4.0 五维逐维审计

### 01 地域与 AI 产业生态 → `L1-地域生态`（10.00%）

- **已覆盖**：`城市 AI 岗位生态` 4.23% + `实习合作半径` 2.27%，合计 6.50%。
- **口径污染**：同组还挂了 `L2-地域生态|生活适配` → `地域与气候` 3.50%。气候/生活舒适度**不属于 AI 产业生态**，却被计入 V4 01 的权重合计，使「地域生态」看起来有 10%，其中真正表达产业生态的只有 6.5%。
- **遗漏**：无「是否为一线城市 / 国家级 AI 产业集群」「本地 AI 企业密度与校招渠道」的独立指标；用户明确偏好「中国 AI 产业中心」，但该偏好在库内仅占 **6.50%**，是五个一级维度里语义最窄的一档。

### 02 家庭条件与地理关系 → `L1-成本安排`（5.00%）+ 附加 `L2-地域生态|生活适配`（3.50%）

- **「家庭条件」部分严重缺失**：库内与钱有关的只有 `学费及住宿` 1.51% + `异地与额外支出` 1.24%，合计 **2.75%**，且二者都是**客观费用**，不是「家庭可承受能力 / 是否需要助学贷款 / 家庭支持度」。用户已明确「学费非绝对硬约束」，但系统中没有任何字段表达这一**已确认的放松条件**。
- **「地理关系」部分缺失**：只有 `地域与气候` 3.50%，没有「与家庭所在地距离」「回家成本」「家庭支持网络」。
- **附加映射是死配置**（见 §4.3）：`V4_DIMENSION_MAP` 第 3 项 `("L2-地域生态|生活适配",)` 从未被任何代码读取，等于「家庭条件与地理关系」在展示上仍只指向 5.00%。

### 03 院校、专业与科研平台 → `L1-研究培养`（20.00%）

- **遗漏（用户优先级直接命中）**：用户明确把「**学校与专业实力**」列为优先项，但库内**没有「院校层次 / 学科评估 / 学校品牌对就业的加成」的独立指标**。北邮 211/双一流这类「学校牌子」信息目前无法进入评分，只能以研究资料形式在页面文字里出现。

## 4. 六项审计问题结论

### 4.1 指标是否遗漏或重复

**结论：有遗漏，无数学意义上的重复。**

- **无重复**：任意两个 L3 的全局权重路径互不相交（L1×L2×L3 逐级相乘，合计严格 = 1.0），不存在同一事实被两条指标重复计权。
- **有语义重叠但非重复计权**：`异地与额外支出`（成本安排 1.24%）与 `地域与气候`（地域生态 3.50%）都受「去外地上学」影响，属于**相关性**而非**重复**。这类相关性在加权平均模型里会被放大成事实上的双重表达，需在页面上提示「这两项都受『是否离开家乡』影响」。
- **遗漏清单**（按严重度）：

| # | 遗漏项 | 影响的 V4 维度 | 与用户原则的关系 |
|---|---|---|---|
| G1 | 失败后果 / 一志愿落空代价 | 04 | 直接违背「仅一次机会、不二战」 |
| G2 | 院校层次 / 学校品牌与学科评估 | 03 | 用户优先项「学校与专业实力」 |
| G3 | 家庭可承受能力（主观，非客观费用） | 02 | 用户「学费非绝对硬约束」 |
| G4 | 与家庭地理关系（距离、回家成本） | 02 | 用户「不强制上海、过冷地区不优先」 |
| G5 | 就业质量硬指标（薪资、岗位层级、去向结构） | 05 | 用户优先项「就业质量」 |
| G6 | 调剂可行性 / 调剂培养价值 | 04 | 用户「仅当培养价值足够」 |

### 4.2 家庭条件与地域拆分后是否重复计权

**结论：未重复计权，但拆分方式制造了口径错觉。**

- 数学上：生活适配在「地域生态」组内归一，经济成本在「成本安排」组内归一，**两条链不相交**，不存在重复相加。
- 语义上：V4 02 的名义权重是 5.00%（成本安排），如果把附加的生活适配算进来是 8.50%，但由于附加映射是死配置（见 4.3），页面实际显示 5.00%。**同一个维度在系统里有两个可能答案**，这是展示口径问题，不是计权问题。
- 真正的风险是：`地域与气候` 被同时算进 V4 01（地域生态，因为它在该组内）又被 V4 02 的附加项引用 —— **一个指标归属两个 V4 维度**，若将来启用附加映射就会真正产生跨维度重复表达。

### 4.3 展示权重与实际计算权重是否一致

**结论：决策树页一致；对比矩阵存在「一个维度被展示两次」的问题。**

- ✅ `pages_tree.py::_tree_table` 同时输出 `组内权重`、`组内占比`、`全局权重(%)` 三列，**展示与计算口径一致**，未发现拿组内权重冒充全局权重的情况。
- ❌ **`V4_DIMENSION_MAP` 的第 3 项（附加 code 元组）是死配置**。`v4_label()` 全项目仅在 `pages_tree.py` 被调用，且三处调用**全部传入 L1 code**。因此 `("L2-地域生态|生活适配",)` 从未生效 —— 这正是「V4.0 五维只做了展示映射、未验证计算语义一致性」的具体落点。
- ❌ **`COMPARE_DIMENSIONS` 中 `学校与专业实力` 与 `培养与科研资源` 同时指向 `L1-研究培养`**。对比矩阵会渲染出两行同源数据，用户会以为是两项独立比较维度，实际是同一组权重被展示了两次。**不是重复计权，但是重复展示。**
- ❌ 对比矩阵 `AI 产业生态 → L1-地域生态`，而该组含 `地域与气候` 3.50%，标签与内容不符（同 §3.1）。

### 4.4 情景倍率是否改变用户原始偏好

**结论：会，且改动方向与用户原则冲突。**

实测（归一化后合计均为 1.0）：

| 情景 | 职业发展 | 报考可行性 | 研究培养 | 地域生态 | 成本安排 |
|---|---:|---:|---:|---:|---:|
| 基准 | 35.00% | 30.00% | 20.00% | 10.00% | 5.00% |
| `career` 职业发展优先 | **48.91%** (+13.91) | **20.96%** (−9.04) | 17.47% | 8.73% | 3.93% |
| `admission` 报考可行性优先 | **24.56%** (−10.44) | **47.37%** (+17.37) | 15.79% | 7.89% | 4.39% |
| `research` 科研培养优先 | 29.44% | 22.43% | **35.51%** (+15.51) | 8.41% | 4.21% |

**核心问题**：用户原则是「**长期职业发展优先**」**且**「**高度重视唯一一次考研机会的风险**」—— 这两条必须**同时**成立。但情景机制把它们做成了互斥滑杆：

- 选 `career`：报考可行性被压到 20.96%，等于淡化「唯一一次机会」的风险；
- 选 `admission`：职业发展被压到 24.56%，等于放弃「长期职业发展优先」。

**没有任何一个情景能同时表达用户的真实偏好。** 情景倍率在这里不是"敏感性分析工具"，而是把用户原本**不可交换**的两条原则变成了可交换的权重。

### 4.5 双目标是否符合真实择校逻辑

| 目标 | required_groups | require_confirmed_2028 | 实测聚合权重 |
|---|---|---|---|
| A `training_value` 是否值得读 | `研究培养` | 否 | 职业发展 55.12% / 研究培养 31.50% / 地域生态 9.45% / 成本安排 3.94% / 报考可行性 0% |
| B `first_choice_value` 是否值得押上唯一一次机会 | `报考可行性` | **是** | 报考可行性 43.48% / 职业发展 40.58% / 研究培养 8.70% / 成本安排 4.35% / 地域生态 2.90% |

- ✅ **A/B 分离本身正确**：A 把报考可行性相关度设为 0（从分母剔除，不是给 0 分），符合"读了值不值"与"考不考得上"应分开的真实逻辑。
- ✅ **B 强制 2028 资格确认**正确：唯一一次机会不能建立在未确认资格上。
- ⚠️ **A 的必备分组选错**：A 必备「研究培养」，但用户最看重的是「**培养价值 / 就业质量**」（就业质量在「职业发展」）。若一条路径职业发展证据齐全、研究培养缺失，A 会输出"暂无法判断"，与用户直觉相反。
- ⚠️ **两个目标都没有「失败后果」输入**（同 G1）：B 只检查 2028 资格是否确认，不检查"落空代价"。
- ⚠️ 相关性矩阵（`0.0 / 0.8 / 0.6 / 0.5 / 0.3 / 0.2 / 1.0`）**全部是演示值，无用户确认依据**。

### 4.6 演示权重是否可能被误认为用户确认权重

**结论：风险确实存在，且发生在最重要的页面上。**

实测 grep 结果：

| 页面 | 是否出现「演示 / 待确认」提示 |
|---|---|
| `pages_tree.py`（决策树） | ✅ 有（配置表"性质"列、情景 warning、修改后仍为演示的 warning、页尾说明） |
| `pages_profile.py`（决策档案） | ✅ 有（3 处） |
| **`pages_cockpit.py`（决策驾驶舱）** | ❌ **完全没有** |
| **`pages_explore.py`（院校探索）** | ❌ **完全没有** |
| **`pages_compare.py`（多校对比）** | ❌ **完全没有** |
| **`pages_risk.py`（风险与路径规划）** | ❌ **完全没有** |

即：**用户在驾驶舱、对比页、风险页看到的任何基于权重的排序与评分，页面上都没有告诉你这是演示配置**。唯一的配置确认入口在「动态决策树 → 配置管理」，用户很可能根本不会点进去。

附带的第二层风险：在决策树页修改演示配置后，`is_demo` **保持 True**（页面已 warning，但只是提示，不阻止）。用户改完权重后极易以为"我已经设成我的偏好了"，实际状态仍是「演示配置（待确认）」。

## 5. 硬约束 / 优先级偏好 / 可补偿权重 三分现状

用户明确要求区分这三类。实测现状：

| 类别 | 应有内容 | 系统现状 | 判定 |
|---|---|---|---|
| **硬约束**（三态，不满足即排除） | 全日制、专业代码可接受、其他 | `HardConstraintFacts` 仅 3 字段：`full_time_ok` / `program_code_acceptable` / `other_constraints_ok` | ⚠️ 部分 |
| | **「仅一次考研机会、不二战」** | **未建模**。仅作为 `USER_CONFIRMED_BACKGROUND` 里的一行文字常量，不参与任何判定 | ❌ 缺失 |
| | **「接受数学一」（已解除的约束）** | 未建模 | ❌ 缺失 |
| **优先级偏好**（排序，不是权重） | 培养价值 / 就业质量 / 学校与专业实力 | **无独立建模**，全部折算成 35/20/30 的权重比例 | ❌ 缺失 |
| **可补偿权重**（加权平均） | 其余可权衡项 | 全部 L1–L3 共 33 个节点均按加权平均处理 | ⚠️ 过度使用 |

**核心结论**：系统目前把**全部**决策因素都当成可补偿权重处理。而用户「不二战」是不可补偿的——它不是"风险权重高一点"，而是"失败后果是终局性的"。把它放进加权平均（如 `career` 情景下倍率 0.8，等于把风险重要性下调 20%）在语义上是错的。

同理，「培养价值 / 就业质量 / 学校与专业实力」是**优先级排序**（lexicographic），不是权重比例。若 A 校就业质量明显更高，用户不会因为 B 校学费低 + 气候好就在加权平均下选 B。当前模型无法表达这一点。

## 7. 审计结论

1. **计算内核是干净的**：三级权重严格归一为 1.0、无空组、无负权重、无重复计权路径，`weights.py` 本身没有语义问题。
2. **问题集中在"语义 ↔ 结构"的接缝处**：V4.0 五维映射是**展示层补丁**，没有反向校验计算语义，导致死配置（A-05）、重复展示（A-06）、标签与内容不符（A-11）。
3. **最严重的三处不是数字错，而是建模错**：不二战未建模（A-02）、失败后果缺失（A-03）、情景把不可交换的原则做成可交换（A-04）。这三条直指用户最核心的约束。
4. **最直接的误用风险是 A-01**：四个主要页面展示基于演示权重的输出却不标注，用户极可能把演示值当自己的偏好。
5. **本阶段不修改任何算法**。上述 13 条需用户确认后另行实施；其中 A-01、A-05、A-06、A-11 属于展示层修正，可在不触碰引擎的前提下修复，建议优先。
