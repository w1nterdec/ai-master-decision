## 四、与旧 Excel 的严格性差异（重要）

Python 引擎**比 Phase 3.7C Excel 更严格**，因此不能要求两者结果完全一致：

| 维度 | Phase 3.7C Excel | Phase 4.0 引擎 |
|---|---|---|
| 来源校验 | 仅检查非空 | 校验登记存在性、核验状态、路径适用性、指标支持性、年份 |
| 证据状态 | 无概念 | 候选映射永不自动升级 |
| 冲突 | 仅在文本中提及 | 冲突登记且阻断评分 |
| 2028 资格 | 单一公式 | 需「已核验2028」+ 已核验 2028 来源证据 + 硬约束候选 |
| 双目标 | 无 | A/B 独立输出 |

在**共同支持的计算规则**上（三级权重、情景归一化、覆盖率、加权平均、硬约束三态门槛），
引擎与 Excel 的一致性由 `tests/golden/test_golden_phase37c.py` 逐格验证。

## 五、Phase 4.1 建议优先级

1. **P0｜证据核验工作台**：为 83 个未登记来源与 207 条候选映射提供"补齐来源元数据 → 标注适用年份 → 逐条核验"的界面与批量操作；这是解锁任何评分输出的前置条件。
2. **P0｜2028 目录录入**：2028 招生目录发布后，录入学院码 / 专业码 / 学习方式 / 方向 / 统考计划，并把 `verification_2028` 置为已核验。
3. **P1｜权重与情景编辑器**：把演示配置转为用户确认偏好，落库并保留修改链（服务层已就绪）。
4. **P1｜可视化**：覆盖率热力图、情景对比、双目标状态面板；必须同时显示"证据不足 / 暂无法判断"状态。
5. **P1｜待核问题看板**：直接消费 `audit_log(action=import.open_question)`。
6. **P2｜招生记录结构化**：把自由文本中的计划/录取人数以人工录入方式写入 `admission_record`。
7. **P2｜导师与资源登记**：人工录入 `mentor` / `research_resource` 并通过 `resource_path_link` 关联可进入性。
8. **P2｜调剂与就业路径建模**：在 `path_kind` 基础上实现推荐规则。
9. **P3｜快照与版本管理**：为每次决策输出生成不可变快照，配合 Git 做审计追踪。
