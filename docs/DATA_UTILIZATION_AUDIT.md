# 数据利用审计（DATA_UTILIZATION_AUDIT）

> 审计对象：`data/decision.db`（生产库）+ `data/raw/Phase3_7C_情景覆盖率门槛修复版.xlsx`（历史研究载体）+ 全部 `docs/`、`reports/`、`data/raw/`
> 审计目标：**找出"明明已经研究过，但系统没有真正用起来"的数据**，并给出整合方案。
> 审计日期：2026-10-17　|　分支：`feature/phase6-decision-ui`

---

## 0. 一句话结论

项目**已经做过大量五校研究**（Astra 初研、豆包五校、Phase 2A–2D、Phase 3.7C），其中 **207 条逐路径研究证据**沉淀在 `Phase3_7C` Excel 的 `3_2证据映射候选` 表中。

但这些信息**几乎没有被系统利用**：`mentor`、`research_resource`、`admission_record` 三张表全部为空（0 行），`risk` 表根本不存在。系统在页面上只会展示"2028 资格未确认 + 缺口"，而**用户最关心的导师、平台、产业、就业、历史统考名额，全部是黑箱**。

本次修复：把 Excel 研究证据**整理为单一可信源** `data/school_research_consolidated.json`（207 条 + 10 条路径 + 14 条待核问题），**报告与网页共用同一份数据**，不再各自为政。

## 4. 整合方案（本次已落地）

- **单一可信源**：`data/school_research_consolidated.json`（由 Excel `3_2证据映射候选`+`路径`+`待核问题` 导出，207+10+14 条）。
- **报告与网页共用**：`docs/2028_AI_MASTER_DECISION_REPORT.md` 与"择校结果总览"页面均读此 JSON，保证一致。
- **证据分级贯穿**：JSON 中每条保留 `grade`（S1官方/S2学院级/S3实验室级/S4全校线索）、`verify_status`、`match_limit`，页面与报告据此标注"历史研究判断 / 2028 正式资格未确认"。
- **不改库结构**：未重建 `decision.db`，未新增表；`mentor/research_resource/admission_record` 的正式入库留待 2028 目录发布后一次性结构化。

---

## 5. 数据质量红线（务必遵守）

1. Excel 研究证据**均为 2023–2027 历史事实或学院级资源**，**没有一条是 2028 官方招生确认**。
2. 任何"导师可进入 085410 某方向""平台对本路径开放"均属**推断**（Excel 自身 `match_limit` 已标注"仅学院/专业级关联；未证该方向或导师可进入"）。
3. 北邮 43/89/132 为**目录计划数（含推免）**；其余四校的"统考约 X"是**历史复试口径推算**，**不得**当作 2028 统考名额或录取概率。
4. 全部研究结论必须与"2028 正式资格未确认"并列展示，不得用历史研究替代 2028 资格判定。
