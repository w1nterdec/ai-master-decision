# 决策规则规范（Phase 4.0 引擎权威口径）

> 本文件是决策引擎的**规范来源**。代码与本文件冲突时，以本文件为准并修正代码。
> 默认权重、默认情景倍率、默认目标相关度矩阵均为**演示配置**，不是用户最终偏好。

---

## R0. 通用不变量

| 编号 | 规则 |
|---|---|
| R0-1 | 引擎不生成、不存储、不输出任何录取概率或录取预测字段。输出结构由 `assert_no_admission_probability` 强制自检。 |
| R0-2 | 空白评分保持「未知」，**不计 0 分**，也不计入覆盖率分子。 |
| R0-3 | 缺失数据不参与加权平均分母：加权分 = Σ(有效分×权重) / Σ(有效权重)。 |
| R0-4 | 所有除法的分母为 0 时返回 0 权重 / 空结果，禁止产生 `NaN`、`Inf` 或默认均分。 |
| R0-5 | 引擎不读 Excel、不访问网络、不依赖任何 UI 框架。 |
| R0-6 | 历史数据只代表其对应年份，不得推断为 2028 正式招生情况。 |

## R1. 硬约束引擎（C1）

输入：三个三态约束（全日制符合、接受专业代码、其他硬约束符合）+ 2028 核验状态 + 是否存在已核验 2028 来源证据。

| 条件 | 准入状态 |
|---|---|
| 任一约束为「否」 | `排除` |
| 无「否」且存在「待确认」 | `待核验` |
| 全部为「是」 | `候选`（**历史候选**，不等于 2028 正式资格） |

2028 资格：

| 条件 | 2028 资格 |
|---|---|
| 2028 核验状态 ≠ 已核验2028 | `2028资格未确认` |
| 已核验2028 但缺少支持该路径的已核验 2028 来源证据 | `2028资格未确认` |
| 已核验2028 + 有已核验证据 + 准入为排除 | `未满足` |
| 已核验2028 + 有已核验证据 + 准入为候选 | `2028正式资格已确认` |

> 规则要点：**任何尚未核验的 2028 招生信息不得标记为已确认**。

对评分输出的强制状态（优先级高于覆盖率）：

- 排除 → `硬约束不符-排除`
- 待核验 → `硬约束待确认-不可比较`
- 候选 → 交由覆盖率判断

## R2. 三级动态权重（C2）

- 结构：一级（5）→ 二级（10）→ 三级（18）。
- 归一化：每一级在**同级组内**归一化；三级全局权重 = 一级归一 × 二级组内归一 × 三级组内归一。
- 合计：18 个三级全局权重合计恒为 1.0（100%），由 `WeightTree.validate()` 校验。
- 负权重：一律拒绝（`NegativeWeightError`）。
- 零权重分组：组内合计为 0 时，该组全部成员权重为 0，登记到 `empty_groups`，**不做除法、不抛异常**。
- 修改任意层权重后自动重算（返回新的不可变 `WeightTree`）。
- 权重修改记录写入 `audit_log`。
- 默认配置 `phase37c_demo` 的 `is_demo=True`。

默认演示权重（来源：Phase 3.7C「三级指标树」M 列）：

## R3. 证据评分闸门（C3）

评分只允许 1、2、3、4、5。有效评分必须**同时**满足：

1. 合法整数评分（布尔值不算整数；`4.0` 视为整数 4；`4.5` 拒绝）；
2. `source_id` 非空；
3. `source_id` 在 `evidence_source` 中**存在**；
4. 来源核验状态为「已核验」（待核验 / 来源冲突 / 已失效 / 无法核验 / 未登记 全部拒绝）；
5. 存在事实声明把该来源关联到**当前路径**；
6. 该声明**支持当前指标**；
7. 声明状态为「已核验」且 `is_candidate=False`（候选映射永不自动升级）；
8. 证据适用年份包含评价年份（`year_window` 默认 0，即精确命中）；
9. 该来源无未解决冲突。

- 空白 → `未知`（不计零分）
- 标记为「不适用 / NA」→ `未知`
- 其余 → `无效`，不计入覆盖率

**与旧 Excel 的差异（U-01 修复）**：Phase 3.7C 仅检查「评分 ∈ {1..5} 整数 且 来源ID 非空」，即"格式有效"。
本引擎默认使用严格闸门。为与 Excel 做黄金比对提供 `LegacyPhase37CGate`（**仅用于测试，禁止用于生产决策**）。

## R4. 覆盖率与缺失处理（C4）

- 指标数量覆盖率 = 有效指标数 / 指标总数。
- 权重覆盖率 = Σ(有效指标权重) / Σ(全部指标权重)，按**当前权重口径**计算。
- 每个情景/目标使用各自权重口径的覆盖率独立判断。
- 默认门槛 0.8（沿用 Phase 3.7C 演示门槛），可通过 `EngineConfig.coverage_threshold` 配置。
- 覆盖率不足 → 输出「证据不足」，分数为空。
- **禁止以缺失数据为零分**。

## R5. 情景分析（C5）

| 情景代码 | 名称 | 倍率（按一级指标） |
|---|---|---|
| `base` | 基础 | 无倍率（使用基础全局权重） |
| `career` | 职业发展优先 | 职业发展 1.6 / 报考可行性 0.8 / 研究培养 1.0 / 地域生态 1.0 / 成本安排 0.9 |
| `admission` | 报考可行性优先 | 0.8 / 1.8 / 0.9 / 0.9 / 1.0 |
| `research` | 科研培养优先 | 0.9 / 0.8 / 1.9 / 0.9 / 0.9 |

- 情景权重 = 基础全局权重 × 倍率，然后**独立归一化**（该情景内合计 100%）。
- 负倍率拒绝；倍率全 0 时防除零返回全 0。
- **每个情景使用自身覆盖率判断是否输出评分**；基础情景达标不得让其它情景输出评分。

## R6. 双目标决策（C6）

两个目标独立输出，禁止复制同一综合分。

### A. 培养与职业价值评估（是否值得读）

- 相关度矩阵（一级指标 → 相关度）：职业发展 1.0、研究培养 1.0、地域生态 0.6、成本安排 0.5、**报考可行性 0.0**。
- 相关度为 0 表示该指标**不在该目标评价范围内**（从权重分母剔除），**不是给 0 分**。
- 必备分组：`研究培养`，其自身覆盖率须达门槛，否则输出「暂无法判断」。
- 不要求 2028 资格已确认（"值不值得读"是条件性判断）。

### B. 一志愿报考价值评估（是否值得投入唯一一次考研机会）

- 相关度矩阵：报考可行性 1.0、职业发展 0.8、成本安排 0.6、研究培养 0.3、地域生态 0.2。
- 必备分组：`报考可行性`。
- **额外要求 2028 正式资格已确认**；否则输出「暂无法判断」。

### 状态取值

| 状态 | 触发条件 |
|---|---|
| `可输出` | 覆盖率达标且必备分组达标 |
| `待补充证据` | 目标口径覆盖率不足 |
| `暂无法判断` | 必备分组证据不足，或 B 目标 2028 资格未确认 |
| `待核验` | 硬约束待核验 |
| `已排除` | 硬约束排除 |

## R7. 调剂与直接就业

Phase 4.0 仅建立数据结构与状态接口：

- `admission_path.path_kind` 区分 `一志愿 / 调剂 / 直接就业`；
- 调剂路径与一志愿路径拥有不同 `path_key`，记录互不混淆；
- 本阶段**不**实现调剂推荐算法与就业路径评分，留待 Phase 4.2+。

## R8. 导入规则（Task D）

1. 保留原始字段（`raw_row` / `raw_row.variants` 全量留痕）。
2. 引用但未登记的 `source_id` 记为「未登记」来源，**不得**视为已核验。
3. 不确定字段一律标记待核验，不擅自补全未知值（不推断专业名称、不推断适用年份）。
4. 不生成模拟招生事实（人数、录取概率、科目年份一律不推断）。
5. 演示权重标记 `is_demo=True`。
6. 历史路径一律以「2028 未确认」导入。
7. 幂等：`batch_key = sha256(文件)[:16]@profile` + 各实体自然键 get_or_create。
