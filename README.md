# 2028 AI 硕士择校工作台 · v1.1.0

把研究变成选择依据：探索招生路径、检索原文、并列比较、核验来源，再保存自己的判断。

面向一次考研机会的 AI / LLM / 具身智能方向研究。当前收录 **5 校、10 条招生路径、207 条逐路径研究映射**，包含导师、平台、就业、考试科目和历史招生线索。**这是个人研究与决策辅助系统，不是录取预测或全国实时院校库。**

## 本次改进

- 研究资料库：全文搜索，学校 / 路径 / 主题 / 来源层级筛选，分页阅读，筛选结果 CSV 和研究原件 Excel 下载。
- 探索到对比：路径详情可读对应历史资料并加入对比；对比按主题呈现真实原文和适用限制。同校同专业不同学院分别保留。
- 手机与桌面功能一致：主内容区可导航到所有业务和管理页；窄屏表格改为完整字段卡片，可在“阅读设置”切换回可搜索、排序、下载的交互表格。表单、权重修改、档案与下载共用同一套业务逻辑。
- 数据追溯：每条研究有底稿表名、行号、来源编号；整合 JSON 有源文件指纹，并在 CI 中与 Excel 全量比对。
- 工程修复：关注后驾驶舱异常、对比列覆盖、来源失效和冲突展示、档案原子保存、可重复初始化与独立测试数据。

详细问题、对标来源、修复与边界见 [产品审查](docs/PRODUCT_REVIEW.md)。

## 快速启动

需要 Python 3.11 或更高版本。建议在项目虚拟环境安装。

Windows PowerShell：

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e ".[dev]"
.\.venv\Scripts\python.exe scripts/bootstrap.py
.\.venv\Scripts\python.exe -m streamlit run app.py
```

macOS / Linux：

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -e ".[dev]"
python scripts/bootstrap.py
python -m streamlit run app.py
```

打开 <http://localhost:8501>。初始化从已入库研究原件生成数据库、重放已归档官方历史证据，再导出研究 JSON；可重复执行，不清空既有数据或升级历史候选声明。旧版只运行 `import_excel.py` 会缺少官方历史证据，推荐使用完整初始化命令。

研究资料库、择校结果总览不依赖数据库，其余页面需要初始化。若使用手机浏览器访问本机服务，需要手机可达的服务器地址；`localhost` 只代表访问设备自身。页面本身会按屏宽适配。

## Docker

```bash
docker compose up --build -d
```

默认仅发布到本机 `127.0.0.1:8501`。非 root 运行，启动时幂等初始化，SQLite 和个人档案保存在 `decision-state` 持久卷。`docker compose down` 保留卷；删除卷会丢失本地状态。若已有服务占用 8501，请调整 Compose 左侧宿主机端口。

这是个人实例，不包含多用户账户与档案隔离；不要把同一实例当作多人协作服务。

## 页面与工作流

1. **决策驾驶舱**：研究入口、资格状态、缺口、用户关注与四层解释。
2. **院校探索**：按学校 / 地点 / 科目 / 角色筛选路径，查看事实、研究原文，加入对比或记录判断。
3. **多校对比**：最多四条具体路径的事实字段和主题原文并列查看，可导出关联研究。
4. **动态决策树**：指标树、权重、情景、偏好配置版本及修改审计。
5. **风险与路径规划**：一志愿、调剂、就业准备与待补证据。
6. **我的决策档案**：关注、候选、暂不考虑、理由、备注及 Markdown 导出。
7. **择校结果总览**：历史分析师意见、研究分组与敏感性；需要按最新证据复核。
8. **研究资料库**：全部研究材料的检索、筛选、原件定位和导出。
9. **高级功能**：证据登记核验、路径维护、模型参数、分析与系统状态。

并行研究两三条候选路径不等于同时报考多校，最终一志愿需要确定一条。

## 数据与可信度

- `data/raw/Phase3_7C_情景覆盖率门槛修复版.xlsx` 是研究原件。
- `data/school_research_consolidated.json` 是原件完整投影，包含 207 条逐路径映射；相同研究可能关联多个路径，数量不等于独立来源数。
- `data/decision.db` 是本地数据库，包含来源、声明、关联、指标、评分、路径和审计；不入版本库。
- `data/decision_profile.json` 是个人档案，不入版本库，采用原子替换写入。
- 资料没有自动联网更新。快照中没有可确认 2028 资格的目录，不能据此宣称全网尚未发布。
- 来源层级 S1–S4 表示材料的出处范围，**不等于核验状态**。来源编号缺少原文链接时必须回查底稿，不应当作已核验证据。
- 历史研究判断与 2028 正式资格分开；候选声明不自动升级；未知不补零；未解决冲突阻断有效依据；不输出录取概率或虚构排名。

现有文字资料已用于检索与对比，但导师、科研资源、招生名额尚未完整结构化。不能从描述自行推算统考名额；目录计划 / 统考计划 / 实际录取要分开核验。报告见 [择校研究结论](docs/2028_AI_MASTER_DECISION_REPORT.md)。

更新流程：修改研究原件 → `python scripts/bootstrap.py` → `python scripts/check_data.py` → 核查分析师意见与新证据是否一致。JSON 更新不会自动改写人工撰写的研究结论。

## 验证与持续集成

```bash
python scripts/check_data.py
python -m ruff check .
python -m pytest
```

测试从已入库原件创建临时数据库并重放历史证据，不依赖个人生产库或被忽略的历史备份，不修改个人档案。覆盖引擎、资格闸门、黄金比对、集成、真实 Streamlit 控件交互以及新增的研究和跨端工作流。

GitHub Actions 在 Linux / Python 3.11 和 Windows / Python 3.12 运行同样的初始化、数据一致性、静态检查、测试步骤，并上传 JUnit 结果。Ruff 当前检查语法和未定义名称等阻断性错误；未声称完成全仓库格式迁移。

环境变量：

- `DECISION_DB_PATH`：数据库路径。
- `DECISION_ARCHIVE_PATH`：个人档案路径。
- 对外部署用的独立认证代理：`scripts/secure_web_launch.py`，凭据仅从 `AUTH_USER` / `AUTH_PASS` 环境变量读取。正式公开部署前仍需验证代理、HTTPS 与访问隔离。

技术实现保留 Streamlit + SQLAlchemy + Pydantic + SQLite，研究查询在服务层，通用跨端组件在 `ui/theme.py`，资格与评分仍由原决策引擎计算。版本范围见 `pyproject.toml`。
